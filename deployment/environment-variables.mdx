## Overview

DRAIT Mini-MES uses environment variables to configure all services. These variables are defined in a `.env` file in the project root and consumed by Docker Compose and the application services.

<Steps>
  <Step title="Create your environment file">
    Copy the example file to create your configuration:

    <CodeGroup>
    ```bash Linux/macOS
    cp .env.example .env
    ```

    ```powershell Windows
    Copy-Item .env.example .env
    ```
    </CodeGroup>
  </Step>

  <Step title="Edit the .env file">
    Open `.env` in your text editor and customize the values:

    ```bash
    nano .env
    # or
    vim .env
    # or use your preferred editor
    ```
  </Step>

  <Step title="Apply changes">
    After modifying `.env`, restart the services:

    ```bash
    docker compose up -d
    ```
  </Step>
</Steps>

<Warning>
  **Security Critical:** Never commit the `.env` file to version control. It should be listed in `.gitignore` and contain sensitive credentials.
</Warning>

## Global Configuration

These variables affect multiple services across the deployment.

### NODE_ENV

<ParamField path="NODE_ENV" type="string" default="development">
  Application environment mode.

  **Accepted values:**
  - `development` - Development mode with verbose logging and hot reload
  - `production` - Production mode with optimized performance and minimal logging

  **Used by:** Backend service

  **Example:**
  ```bash
  NODE_ENV=production
  ```

  <Note>
    In production, set this to `production` to enable optimizations and reduce log verbosity.
  </Note>
</ParamField>

### TZ

<ParamField path="TZ" type="string" default="America/Buenos_Aires">
  Timezone for all services. Used for timestamping logs and database operations.

  **Format:** IANA timezone identifier

  **Common values:**
  - `UTC` - Coordinated Universal Time
  - `America/New_York` - Eastern Time (US & Canada)
  - `America/Los_Angeles` - Pacific Time (US & Canada)
  - `Europe/London` - United Kingdom
  - `Europe/Paris` - Central European Time
  - `Asia/Tokyo` - Japan Standard Time
  - `America/Buenos_Aires` - Argentina Time

  **Used by:** All services (database, backend, frontend)

  **Example:**
  ```bash
  TZ=America/New_York
  ```

  <Info>
    [View complete list of timezone identifiers](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones)
  </Info>
</ParamField>

## Database Configuration

PostgreSQL database settings for data persistence.

### POSTGRES_DB

<ParamField path="POSTGRES_DB" type="string" default="drait_mes">
  Name of the PostgreSQL database to create and use.

  **Used by:** PostgreSQL container and backend connection

  **Example:**
  ```bash
  POSTGRES_DB=drait_mes
  ```

  <Warning>
    Changing this value after initial setup requires database migration or data loss.
  </Warning>
</ParamField>

### POSTGRES_USER

<ParamField path="POSTGRES_USER" type="string" default="drait">
  PostgreSQL database username.

  **Used by:** PostgreSQL container and backend connection

  **Example:**
  ```bash
  POSTGRES_USER=drait_admin
  ```

  <Note>
    If you change this value, ensure it matches in the `DATABASE_URL` variable.
  </Note>
</ParamField>

### POSTGRES_PASSWORD

<ParamField path="POSTGRES_PASSWORD" type="string" default="drait123">
  PostgreSQL database password.

  **Used by:** PostgreSQL container and backend connection

  **Example:**
  ```bash
  POSTGRES_PASSWORD=MyS3cur3P@ssw0rd!
  ```

  <Warning>
    **Security Critical:** Always change this from the default value in production. Use a strong password with:
    - Minimum 12 characters
    - Mix of uppercase, lowercase, numbers, and special characters
    - No dictionary words
  </Warning>
</ParamField>

### POSTGRES_PORT

<ParamField path="POSTGRES_PORT" type="number" default="5432">
  Host port to expose PostgreSQL on.

  **Used by:** Docker Compose port mapping

  **Example:**
  ```bash
  POSTGRES_PORT=5432
  ```

  <Info>
    This port is exposed on the host for external database access. In production, consider removing this exposure by commenting out the `ports` section in `docker-compose.yml` if external access is not needed.
  </Info>
</ParamField>

### DATABASE_URL

<ParamField path="DATABASE_URL" type="string" required>
  Complete PostgreSQL connection string used by Prisma ORM.

  **Format:** `postgresql://[user]:[password]@[host]:[port]/[database]?schema=public`

  **Components:**
  - `user` - Must match `POSTGRES_USER`
  - `password` - Must match `POSTGRES_PASSWORD`
  - `host` - Container name (`drait-db`) or `localhost` for external connections
  - `port` - Internal port (always `5432` inside containers)
  - `database` - Must match `POSTGRES_DB`
  - `schema` - PostgreSQL schema (typically `public`)

  **Used by:** Backend service (Prisma)

  **Default:**
  ```bash
  DATABASE_URL=postgresql://drait:drait123@drait-db:5432/drait_mes?schema=public
  ```

  **For external access (from host machine):**
  ```bash
  DATABASE_URL=postgresql://drait:drait123@localhost:5432/drait_mes?schema=public
  ```

  <Warning>
    Ensure this URL matches your other database environment variables. Mismatched credentials will cause connection failures.
  </Warning>
</ParamField>

## Backend Configuration

NestJS backend API server settings.

### BACKEND_PORT

<ParamField path="BACKEND_PORT" type="number" default="3000">
  Internal port the backend service listens on inside its container.

  **Used by:** Backend service

  **Example:**
  ```bash
  BACKEND_PORT=3000
  ```

  <Note>
    This is the internal container port. The backend is not directly exposed to the host; it's accessed via Nginx reverse proxy at `/api/*`.
  </Note>
</ParamField>

### JWT_SECRET

<ParamField path="JWT_SECRET" type="string" default="change_this_secret">
  Secret key used to sign and verify JSON Web Tokens for authentication.

  **Used by:** Backend authentication module

  **Example:**
  ```bash
  JWT_SECRET=a8f5f167f44f4964e6c998dee827110c
  ```

  <Warning>
    **Security Critical:** This is the most important security setting. You MUST change this in production:
    - Use a cryptographically secure random string
    - Minimum 32 characters recommended
    - Never reuse across environments
    - Never commit to version control
    
    Generate a secure secret:
    ```bash
    # Linux/macOS
    openssl rand -hex 32
    
    # Or
    node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
    ```
  </Warning>
</ParamField>

### JWT_EXPIRES_IN

<ParamField path="JWT_EXPIRES_IN" type="string" default="8h">
  JWT token expiration time. Users must re-authenticate after this period.

  **Format:** Time string (e.g., `60s`, `30m`, `8h`, `7d`)

  **Units:**
  - `s` - seconds
  - `m` - minutes
  - `h` - hours
  - `d` - days

  **Used by:** Backend authentication module

  **Examples:**
  ```bash
  # 8 hours (default, suitable for shop floor workers)
  JWT_EXPIRES_IN=8h

  # 30 minutes (high security environments)
  JWT_EXPIRES_IN=30m

  # 7 days (convenience, lower security)
  JWT_EXPIRES_IN=7d
  ```

  <Note>
    Consider your use case:
    - Shop floor workers: Longer sessions (4-8h) to avoid frequent re-login
    - Administrative users: Shorter sessions (1-2h) for higher security
    - Public kiosks: Very short sessions (15-30m)
  </Note>
</ParamField>

### CORS_ORIGIN

<ParamField path="CORS_ORIGIN" type="string" default="http://localhost">
  Allowed origin for Cross-Origin Resource Sharing (CORS). Determines which domains can make API requests.

  **Used by:** Backend CORS middleware

  **Examples:**
  ```bash
  # Single origin (development)
  CORS_ORIGIN=http://localhost

  # Single origin (production)
  CORS_ORIGIN=https://mes.yourdomain.com

  # Multiple origins (comma-separated)
  CORS_ORIGIN=https://mes.yourdomain.com,https://mes-staging.yourdomain.com

  # Allow all (NOT recommended for production)
  CORS_ORIGIN=*
  ```

  <Warning>
    **Security:** In production, set this to your actual domain. Never use `*` in production as it allows any website to make requests to your API.
  </Warning>
</ParamField>

## Frontend Configuration

React + Vite frontend application settings.

### VITE_API_BASE_URL

<ParamField path="VITE_API_BASE_URL" type="string" default="/api">
  Base URL path for API requests from the frontend.

  **Used by:** Frontend API client

  **Format:** Relative or absolute URL

  **Examples:**
  ```bash
  # Relative path (via Nginx proxy, recommended)
  VITE_API_BASE_URL=/api

  # Absolute URL (direct backend access, not recommended)
  VITE_API_BASE_URL=http://localhost:3000/api

  # Production domain
  VITE_API_BASE_URL=https://api.yourdomain.com/api
  ```

  <Note>
    The default `/api` value works with the included Nginx configuration, which proxies `/api/*` requests to the backend service.
  </Note>

  <Warning>
    This variable is baked into the frontend build. If you change it, you must rebuild the frontend container:
    ```bash
    docker compose up --build -d drait-frontend
    ```
  </Warning>
</ParamField>

## Nginx Configuration

Reverse proxy server settings.

### HTTP_PORT

<ParamField path="HTTP_PORT" type="number" default="80">
  Host port to expose the application on.

  **Used by:** Docker Compose port mapping for Nginx

  **Examples:**
  ```bash
  # Standard HTTP port
  HTTP_PORT=80

  # Alternative port (if 80 is in use)
  HTTP_PORT=8080

  # High port for non-root user
  HTTP_PORT=3080
  ```

  <Info>
    If you change this from `80`, access the application at `http://localhost:[PORT]/`
    
    Example: `HTTP_PORT=8080` → `http://localhost:8080/`
  </Info>
</ParamField>

## Complete Example

Here's a complete `.env` file with production-ready values:

```bash .env
# Global
NODE_ENV=production
TZ=America/New_York

# Database
POSTGRES_DB=drait_mes
POSTGRES_USER=drait_admin
POSTGRES_PASSWORD=x8K#mP2$vL9@qN4&wR7*eT5^yU3!iO6%
POSTGRES_PORT=5432
DATABASE_URL=postgresql://drait_admin:x8K#mP2$vL9@qN4&wR7*eT5^yU3!iO6%@drait-db:5432/drait_mes?schema=public

# Backend
BACKEND_PORT=3000
JWT_SECRET=f8a7c3d2e1b4a5d6c7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0

CORS_ORIGIN=https://mes.yourdomain.com

# Frontend

# Nginx

```

## Validation Checklist

Before deploying, verify your configuration:

<Accordion title="Security Checklist">
  - [ ] `POSTGRES_PASSWORD` changed from default
  - [ ] `JWT_SECRET` changed to a cryptographically secure random string (32+ characters)
  - [ ] `CORS_ORIGIN` set to your actual domain (not `*`)
  - [ ] `.env` file is in `.gitignore` and not committed to version control
  - [ ] `NODE_ENV=production` for production deployments
</Accordion>

<Accordion title="Configuration Consistency">
  - [ ] `DATABASE_URL` username matches `POSTGRES_USER`
  - [ ] `DATABASE_URL` password matches `POSTGRES_PASSWORD`
  - [ ] `DATABASE_URL` database name matches `POSTGRES_DB`
  - [ ] `DATABASE_URL` host is `drait-db` (not `localhost`)
  - [ ] `VITE_API_BASE_URL` is `/api` when using Nginx proxy
</Accordion>

<Accordion title="Network Ports">
  - [ ] `HTTP_PORT` is available on your host system
  - [ ] `POSTGRES_PORT` is available (or remove exposure in production)
  - [ ] Firewall rules allow access to `HTTP_PORT`
</Accordion>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Environment changes not taking effect">
    After modifying `.env`, you must restart the services:
    ```bash
    docker compose down
    docker compose up -d
    ```

    For `VITE_API_BASE_URL` changes, rebuild the frontend:
    ```bash
    docker compose up --build -d drait-frontend
    ```
  </Accordion>

  <Accordion title="Database connection errors">
    Verify:
    1. `DATABASE_URL` credentials match `POSTGRES_USER` and `POSTGRES_PASSWORD`
    2. Host in `DATABASE_URL` is `drait-db` (not `localhost`)
    3. Database is healthy: `docker compose ps drait-db`
    4. Check logs: `docker compose logs drait-db`
  </Accordion>

  <Accordion title="CORS errors in browser console">
    Check:
    1. `CORS_ORIGIN` matches the URL you're accessing (including protocol and port)
    2. No trailing slash in `CORS_ORIGIN`
    3. Restart backend after changing: `docker compose restart drait-backend`
    
    Example error:
    ```
    Access to fetch at 'http://localhost/api/...' from origin 'http://localhost:8080' 
    has been blocked by CORS policy
    ```
    
    Solution: Set `CORS_ORIGIN=http://localhost:8080`
  </Accordion>

  <Accordion title="JWT authentication failures">
    Ensure:
    1. `JWT_SECRET` is set and not empty
    2. `JWT_SECRET` has not changed since users logged in (changing it invalidates all existing tokens)
    3. `JWT_EXPIRES_IN` format is valid (e.g., `8h`, not `8 hours`)
  </Accordion>

  <Accordion title="Port already in use">
    If you see errors like `bind: address already in use`, change the conflicting port:
    
    ```bash
    # For HTTP
    HTTP_PORT=8080
    
    # For PostgreSQL
    POSTGRES_PORT=5433
    ```
    
    Then restart:
    ```bash
    docker compose down
    docker compose up -d
    ```
  </Accordion>
</AccordionGroup>
